# 출시 전 라이브 보드 정리 — QA 계정 숨김 런북

출시일 **2026-11-17** 전에 라이브 리더보드("전체" 탭)와 대전 기록에서 테스트 계정의 점수를 숨긴다.
근거: `docs/qa/2026-10-25-review.md` #5 (QA 계정 `QAb A1Z`, `QATEST`, `QA-B2`, 그리고 `민황`이 상위권에 노출됨, AURORA 기록 포함).
코드 변경 없음. 서버에 있는 운영 RPC 두 개만 쓴다.

| 도구 | 하는 일 | 되돌리기 |
|---|---|---|
| `admin_set_hidden(p_id, true)` | 그 플레이어의 `fw_scores`·`fw_versus` 행을 모두 숨김(보드·친구·대전 기록에서 빠짐). 점수 자체는 지우지 않음 | `admin_set_hidden(p_id, false)` |
| `admin_tester_set(p_id, true, note)` | 테스터 표시(출시된 모든 유닛을 구매 없이 사용). **보드 제외 기능은 아니다**: 표시 뒤에 올린 기록은 다시 숨겨야 한다 | `admin_tester_set(p_id, false)` |

## 절차

1. **로그인** — `admin.html`을 owner 계정으로 연다(이메일 코드 로그인). `mod` 권한이면 숨김까지 가능, 테스터 표시는 owner.
2. **대상 확인** — 플레이어 검색에서 아래 닉네임을 찾고, 각 행의 가입 이메일·가입일로 우리 계정이 맞는지 확인한다.
   - `QAb A1Z`
   - `QATEST`
   - `QA-B2`
   - `민황` — **실제 플레이어일 수 있다.** 가입 이메일이 팀 계정이 아니면 건드리지 않는다.
   닉네임은 누구나 똑같이 적을 수 있으므로 닉네임만 보고 숨기지 않는다. 판단 기준은 `auth.users`의 이메일이다.
3. **숨김** — 확인된 계정마다 `숨김`(= `admin_set_hidden(id, true)`)을 누른다. 보드에서 즉시 빠진다.
4. **테스터 표시** — 같은 계정을 `admin_tester_set(id, true, 'QA 2026-10')`로 표시해 운영 화면에서 QA 계정임이 보이게 한다. 이후 그 계정으로 플레이하면 기록은 다시 보드에 오르므로, QA는 출시 후에는 별도 Supabase 프로젝트(스테이징)에서 하거나, 플레이 뒤 3번을 반복한다.
5. **확인 쿼리** (Supabase SQL 에디터, service role):
   ```sql
   select nick, bird, score from public.fw_scores where hidden order by score desc limit 20;
   ```
   숨긴 계정의 행이 모두 나오면 끝. 보이지 않는 행이 있으면 2번부터 다시.
