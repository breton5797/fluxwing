# SWISHBY 출시 전 QA 종합 계획 (감사 10건 → 실행 계획)

**한 줄 결론:** 출시를 막는 문제는 다섯 가지입니다. ① 노치 아이폰에서 safe-area가 두 번 적용되는 문제 ② 대시가 끝나는 순간 무적이 먼저 풀려 죽는 버그 ③ 신규 유저가 쓸 수 없는 5초 이어하기 모달 ④ 앱을 내려도 꺼지지 않는 음악 ⑤ 1,300만 점까지 위조되는 리더보드입니다. 모두 S~M 규모라 6개 병렬 패키지로 11-10 제출 전에 끝낼 수 있습니다. 경제·광고·리텐션 구조 변경은 오너 결정 사항으로 분리했습니다.

비유하면 이번 출시는 개업 전날의 식당 점검입니다. 문이 반쯤 가려져 있고(safe-area), 의자 하나가 부러져 있으며(대시 사망), 계산대 앞에서 손님을 5초씩 세워 둡니다(이어하기 모달). 이것부터 고칩니다. 메뉴 개편(미션·이벤트·광고)은 손님 반응을 본 다음에 합니다.

> 중복 병합 결과: 한국어 줄바꿈(3개 감사), 터치 타깃(2), 음악 백그라운드 재생(2), 효과 설정 미번역 및 fxRm(3), 활공 힌트와 배너 넘침(2), 행거 설명 가림(2), 잠금 아이콘 겹침과 작은 글씨(2), 결과 힌트의 'Space'(2)는 각각 한 항목으로 묶었습니다. 근거가 없는 항목은 없어서 빼지 않았습니다.

## P0 출시 전 필수 (11-10 제출 빌드에 포함)
- **safe-area 이중 적용**: 출시 사용자 대부분이 쓰는 노치 아이폰에서 모든 화면이 깨지고, 심사자도 바로 봅니다. CSS 한 줄짜리 원인입니다. → 패키지 `ios-safe-area-layout`
- **대시 출구 사망**: 핵심 메커니즘이 불공정한 죽음을 만듭니다. 코드 주석이 의도와 다르다는 것을 보여 주므로 버그로 판단합니다. → `run-fairness`
- **이어하기 모달 5초 정체**: 신규 유저의 첫 판부터 걸립니다. → `run-fairness`
- **활공 힌트 소실, 배너 넘침**: 튜토리얼 정보가 아무에게도 전달되지 않습니다. → `run-fairness`(배너 그리기) + `ftue-copy-i18n`(힌트 타이밍)
- **데일리로 시작 시 튜토리얼 건너뜀, 데일리 문구 오류**: 신규 유저 첫 경험이 오류입니다. → `ftue-copy-i18n`
- **백그라운드 음악 재생과 음표 몰림**: 리뷰 1점 단골 사유입니다. → `audio-lifecycle`
- **리더보드 위조**: 출시일 첫 소셜 화면의 신뢰 문제입니다. 운영 DB SQL은 오너가 직접 실행해야 합니다. → `leaderboard-security`
- **RTL 하트 가림**: 두 언어에서 생명 정보가 보이지 않습니다. → `ios-safe-area-layout`
